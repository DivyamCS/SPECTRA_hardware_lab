# Golden checksums

Generated by `python tools/golden.py` (Python models of every program, bit-exact with the
firmware) on 16 Oct 2026; `fw/build.py` writes the same values into `fw/golden.h`. These are
exact results, not timing: every switch setting must give the same checksum (a switch may change
the cycle count, never the checksum).

| Program | Image / SW6:5 | What is hashed | Checksum | fw/golden.h |
| --- | --- | --- | --- | --- |
| Game of Life 64x64, 400 generations | demo / 00 | FNV-1a over the bytes of the final grid (generation 400, 4,096 cells) | 0xA556EEC3 | GOLD_GOL |
| Mandelbrot 192x144 (halves and interleaved) | demo / 01, 10 | FNV-1a over the 27,648 iteration-count bytes | 0x22B8E929 | GOLD_MANDEL |
| MatMul 32x32 int32 | demo / 11 | FNV-1a over C as little-endian int32 (4,096 bytes) | 0xC063A00F | GOLD_MATMUL |
| M-extension test | t_mext | each 32-bit result of the 8 M instructions folded in FNV style (h = (h xor r) x 16777619), over all 13 x 13 edge-value pairs and 1,000 LCG pairs | 0xD7A9B563 | GOLD_MEXT |

Check: the four values printed by `tools/golden.py` equal the four `#define`s in `fw/golden.h`
(compared numerically on 16 Oct 2026). The other test images (t_lock, t_barrier, t_hazard,
t_cache) pass by their own counts (lock counter = 10,000 x cores, 0 failed checks), listed in
the README's firmware table.

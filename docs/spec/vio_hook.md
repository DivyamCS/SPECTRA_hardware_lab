# vio_hook (spec v1.1)

| Item | Value |
| --- | --- |
| File | rtl/io/vio_hook.v (Vivado VIO IP `vio_spectra`, generated by a Tcl script, plus the override mux) |
| Testbench | tb/tb_vio_hook.v (stub `vio_0`: synchronisers, override mux, probe inputs) |
| Vectors | directed |
| Interfaces | none (sits between the board pins and switch_cfg / clk_rst / mmio_bus) |
| Removal parameter | `HAS_VIO` = 0: pins pass straight through, no IP |

## Purpose
Lets scripts set the switches, press the buttons and read the LEDs and the 7-segment value over
the JTAG cable, so board regressions run without anyone touching the board (PROTOCOL.md
section 10).

## Ports
| Port | Dir | Width | Meaning |
| --- | --- | --- | --- |
| `clk` | in | 1 | 50 MHz |
| `sw_pin`, `btn_pin` | in | 16, 5 | board switches; buttons BTNC, BTNL, BTNR, BTNU, BTND (bit 0 = BTNC) |
| `sw`, `btn` | out | 16, 5 | to switch_cfg, clk_rst, mmio_bus |
| `leds`, `seg7_val`, `seg7_dp`, `uart_busy` | in | 16, 32, 8, 1 | VIO input probes |

## Behaviour
1. VIO probes: outputs `ovr_en` (1), `ovr_sw` (16), `ovr_btn` (5); inputs `leds`, `seg7_val`,
   `seg7_dp`, `uart_busy` (PROTOCOL.md section 10 table).
2. Every pin goes through a 2-flop synchroniser (ASYNC_REG) first: `sw` = `ovr_en` ? `ovr_sw` :
   `sw_pin` two `clk` edges late, the same for `btn`. So no logic sits between a pin and its first
   flop (CDC-10), and `btn[0]`, the reset request for clk_rst, is a clean flop output. `ovr_en`
   resets to 0, so the board behaves exactly as without the hook until a script enables it.
3. Cost: a few hundred LUTs, no BRAM; the final demo build may keep it with `ovr_en` = 0.

## Reset values
`ovr_en` = 0 (VIO initial value).

## Tests
Mux: pins pass through with `ovr_en` = 0, VIO values with 1. Board: board.tcl sets the
switches and reads the LEDs and SEG7 over JTAG; one physical switch flip still works (needs
the board). PASS = all checks.

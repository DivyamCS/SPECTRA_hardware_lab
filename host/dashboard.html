Two ways to see 1 vs 2 cores. Frame-rate mode (SW5 down): 160 columns; 1 core draws half as many frames (sparse comb, footprints twice as far apart). Detail mode (SW5 up at BTNC): the same frame rate; 1 core draws 80 columns (blocky), 2 cores 160 (sharp). For the full upgrade, play one game with 1 core and I-cache off (SW2, SW7 down + BTNC) and one with 2 cores and I-cache on: both appear under "Settings compared".
Light Hunt. BTNC starts a game and the clock. BTNU / BTND walk, BTNL / BTNR turn. Pick up the five orbs (any order; the beacon glows on the next one), then reach the exit. The board shows the orbs on LED15..11 and "orbs   seconds" on the 7-segment display, then "d0nE" and your time. SW2 = 1 or 2 cores (live). Walking follows real time, so 1 and 2 cores move at the same speed: flip SW2 and only the smoothness (frames per second) changes.

Every demo case: set the switches, then press BTNC

Up = the switch is on. CONFIG is read at reset, so set the switches first and then press BTNC. After each run the 7-segment display tours the results, 3 s per item: cycles (thousands), then for each core the I-cache hit %, D-cache hit % and CPI, and with two cores each core's arbiter wait %. LED15:14 and LED11 show which item it is, with the same meaning as the manual browser; LED13 = core 1; LED10 = tour on. Moving SW15:14 or pressing BTNL / BTNR switches to the manual browser; BTNU starts the tour again. "board" results were measured on the FPGA (docs/results/board_regress.md); the other cases show their numbers on the Live tab after the run.
